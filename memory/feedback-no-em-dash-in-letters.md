---
name: feedback-no-em-dash-in-letters
description: Never use em-dashes (—) in outgoing letters or messages to external people; restructure the sentence instead.
metadata:
  type: feedback
---

When drafting anything that will be sent to a real person outside the team — an email, a LinkedIn message, any outreach text, in any language — never use the em-dash (—, `&mdash;`). Restructure the sentence instead: a comma, a colon, a semicolon, parentheses, or two shorter sentences.

**Why:** Alex flagged this on 2026-07-16 while reviewing the relance drafts. The em-dash is a well-known tell of machine-generated writing; a letter peppered with them stops reading as written by Alex's own hand, and outgoing letters must read as his.

**How to apply:** the rule covers the message body of every outgoing draft (drafts pages like `kb/BizDev/_drafts.md`, reply proposals, DM texts). It does not cover internal documents, plans, or knowledge-base notes, where the dash stays acceptable. When reviewing an existing draft, treat each em-dash as an error to rewrite, not a style preference. Related writing rule: [[feedback-no-hard-line-wraps]].
