When a task needs a tool that is not on the machine, install it and carry on. Do not stop, describe the gap, and wait for permission.

**Why:** on 2026-08-06 I reported that no headless browser was installed and named the one command that would fix it, then stopped. Alex ran the command himself and said: «на будущее, если нужно что-то поставить, бери и ставь.» Waiting for permission on a routine, reversible install costs a whole round trip and produces nothing. This is the same standing wish behind [[feedback_reusable_tooling]] — clear the stone off the path rather than walking around it, and never let a missing toolchain harden into a stated fact about the machine.

**How to apply:** install it, say in one sentence what you installed and why, and keep going. Put it where the consumer of the tool lives, not wherever the shell happened to be. Still name the obstacle out loud — the change is that you name it in the past tense, having already fixed it. This does not extend to actions that destroy data or reach outside the machine: wiping a local database, dropping a volume, or anything that touches a live external system still needs Alex's word.
