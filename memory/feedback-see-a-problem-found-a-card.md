See a problem, found a card. Not "I propose founding a card", not "this is worth a card" — found it, in the same turn you noticed it, and say it is founded, past tense.

**Why:** Alex, 2026-08-08, after I ended a report with "она пока никуда не записана, и я предлагаю завести на неё карточку отдельно": «Не надо предлагать, надо заводить карточку. Есть проблема. Зачем мне предлагать заводить карточку? Заводи карточку, когда ты видишь проблему. Не чинить проблему, а заводить карточку. Это должно быть 1 правило.» Proposing costs him a decision he has already made in general, and a problem that lives only in a chat message is a problem that will be re-discovered later at full price.

**The calibration, added 2026-08-16 on Alex's own instruction:** «давай это поправим, чтобы реально не плодить карточки ради карточек, особенно в отношении харнаса, в отношении машинерии». The rule was being applied so literally that trivial machinery repairs were becoming cards, which is a different waste from the one the rule exists to prevent. So the rule now has a floor.

**Found a card when any one of these is true.** The fix needs a decision that is Alex's or somebody else's to make. It changes product behaviour a user can see. It is bigger than one sitting, or touches several files whose order matters. You cannot fix it right now — something is blocking you, or it lives in another repository or on a server. It will be forgotten if it is not written down somewhere a future session actually reads.

**Do it now and record it in one line when all of these are true.** The fix is obvious, small and reversible; you are already inside the work that exposed it; nobody else has to weigh in; and the whole story of it fits in a commit message or one line in a document that already exists. This is above all the harness and the machinery — a missing rank entry in a configuration file, a stale path, a wrong flag, a leftover row in a generated index. Fix it, commit it on its own so the repair is legible, and name it in the final report. Do not open a card whose writing costs more than the repair it describes.

**What never changes.** Never propose founding a card instead of founding one. Never silently work around a problem you decided not to card — either it is fixed and recorded, or it is a card; there is no third state where it lives only in your own head or in a chat message that scrolls away.

**How to apply:** when a card is right, found it through the project's own founding command, fill it properly, sign it. Same boundary as [[feedback-decide-technical-details-yourself]] seen from the other side — decide small technical details yourself, and now also repair small machinery yourself, but never quietly repair a problem that deserves its own record. Related: [[feedback-resolve-before-reporting]] still holds for obstacles blocking your own current task; [[feedback-never-report-your-own-problems]] holds for anything you caused.
