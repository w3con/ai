On 2026-07-10 the Round A executor was launched with `model: "sonnet"` and genuinely ran `claude-sonnet-5` for all build work (transcript lines 4–111). Alex stopped it and typed questions into it; those resume turns ran on the session model `claude-fable-5` (the global `~/.claude/settings.json` pin `"model": "claude-fable-5[1m]"`), transcript lines 115–147. The agent — at that moment truthfully running as Fable — told Alex "Я — модель Fable 5" and wrongly implied it had done the whole job, causing a false alarm that the Sonnet pipeline was broken. A separate probe confirmed the `model: "sonnet"` override works.

**Why this happened:** the model override lives in the original Agent call; a UI interrupt-resume, or a continuation through the `SendMessage` tool, used to re-enter the agent under the session model rather than the model it was launched with. So an agent's self-identification has only ever answered "what am I NOW", not "what built this" — that fact does not change with the rest of this entry, and it is the one part of the old rule that still holds.

**Confirmed again on 2026-07-10, and it was not only a UI interrupt:** resuming a stopped subagent with the **`SendMessage` tool** did the same thing. A `model: "sonnet"` executor finished checkpoint 1A on `claude-sonnet-5` (22 turns); a `SendMessage` handing it the next checkpoint resumed it on `claude-opus-4-8`, the session model (4 turns), silently. On the strength of that measurement the standing rule became "spawn a fresh agent per phase, never reuse one" — reuse looked like a false economy, because it bought back roughly fifteen thousand Sonnet tokens of cold start and spent the entire remaining phase at Opus prices instead.

**Reversed on 2026-08-01, on Alex's word, because the underlying defect is fixed.** The official Claude Code changelog, cached at `~/.claude/cache/changelog.md`, records under version 2.1.211 the line "Fixed subagents spawned with an explicit model override reverting to the parent's model when resumed or sent a follow-up message" — a word-for-word description of the defect measured above. Dating that fix against this machine's own session transcripts (searching `~/.claude/projects` for the `version` field and taking the earliest timestamp per version) shows that on 2026-07-10, when the defect was found, the machine was running versions 2.1.202, 2.1.205 and 2.1.206; version 2.1.211 first appears on 2026-07-16; the version installed today is 2.1.220, first seen 2026-07-25. Every session run since 2026-07-16 has therefore run on a build that already contains the fix, so the prohibition spent its last three weeks protecting against a problem that no longer existed. Reusing one subagent across the phases of a single piece of work is permitted again, and it saves the cold-start cost the old rule was paying on every single phase.

**What replaces the prohibition is a cheaper, on-demand check, not a blanket setting.** An environment variable named `CLAUDE_CODE_SUBAGENT_MODEL` exists — the same changelog, under version 2.1.147, records "Fixed `CLAUDE_CODE_SUBAGENT_MODEL` not applying to teammate processes spawned by agent teams," which confirms the variable is real and honoured, though not its exact semantics. Setting it pins every subagent process to the one named model no matter how it is resumed, which would make the fixed defect impossible to reintroduce even by accident — but it is recorded here as an available safeguard, not as something to set permanently, because it pins **all** subagents to one model at once, and it is not yet known whether an explicit per-spawn model override would beat it for the cases where Alex genuinely wants one subagent on Opus and another on Sonnet within the same run. Until that is known, leaving it unset and checking the model afterwards, only when the answer actually matters, is the cheaper posture.

**How to apply now:** (1) Reusing a subagent across the phases of one piece of work, by typing into it or by continuing it with `SendMessage`, is permitted — it is no longer assumed to silently change the model underneath the work. (2) When it matters which model actually produced a piece of work — a dispute about quality, a cost reconciliation, anything you would want to defend later — verify it by grepping the transcript output file directly: `grep -o '"model":"[^"]*"' <output_file> | sort | uniq -c`, where the order the lines first appear in gives the chronology of which model ran when. Never rely on the agent's self-report or on the launch parameter alone, because both describe only the turn being asked about, not the history behind it. (3) `CLAUDE_CODE_SUBAGENT_MODEL` is available to pin every subagent to one model if a future measurement shows the defect has returned, or if per-spawn overrides turn out not to be reliable enough on their own; it is not set by default. (4) Cheap sanity probe when in doubt: a no-tools agent with `model: "sonnet"` asked to print its model ID, exactly as before.
